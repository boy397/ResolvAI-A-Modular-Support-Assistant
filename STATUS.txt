UPDATE: RATE LIMIT FIX APPLIED
--------------------------------
"Too many requests" errors were caused by stage 4 (classification baselines)
firing 800+ sequential LLM calls with no delay or retry logic -- free-tier
APIs can't sustain that. Fixed:
  - src/resolvai/utils/llm_client.py now retries on rate-limit errors with
    exponential backoff, and throttles calls to ~1.2s apart by default
    (tested with a simulated flaky call -- confirmed working)
  - params.yaml -> classification.label_sample_size reduced from 800 to 250
    (raise it later once a full run completes cleanly)
  - Reply generation now falls back to the single best-matching historical
    reply (no LLM call) if the API is ever unavailable even after retries,
    instead of crashing
If you still see rate-limit errors after this, raise
MIN_SECONDS_BETWEEN_CALLS in llm_client.py (e.g. to 2.5) and/or lower
label_sample_size further (e.g. to 150).

STEP-BY-STEP: GETTING IT RUNNING WITHOUT ERRORS
==================================================

You said the API key is already in your local .env -- good, that's the main
external dependency handled. Do the following on YOUR machine, in this order:

STEP 1 - Environment setup
---------------------------
    python -m venv venv
    venv\Scripts\activate          (Windows)   or   source venv/bin/activate (Mac/Linux)
    pip install -r requirements.txt

    Watch for: sentence-transformers pulls in torch, which is a large download
    and can take several minutes on first install. This is normal, not an error.

STEP 2 - Get the dataset in place
-----------------------------------
    Download the Kaggle "customer-support-on-twitter" CSV.
    Place it at: data/raw/sample.csv
    (If your file has a different name, either rename it or edit
    config/config.yaml -> data_ingestion.raw_data_path)

STEP 3 - First dry run: just the brand profiling
---------------------------------------------------
    python -m resolvai.pipeline.stage_01_data_ingestion

    Read the printed brand profile table in your terminal / logs/running_logs.log.
    Confirm config/config.yaml -> data_ingestion.chosen_brand is actually the
    brand you want (edit the yaml file directly if you want to change it, then
    re-run this stage).

STEP 4 - Run the full training pipeline
-------------------------------------------
    python main.py

    This runs stages 1-5 in order: ingestion -> thread reconstruction -> intent
    discovery -> classification baselines -> retrieval index build.

    Watch for these likely issues:
    - If it fails on the Groq/Gemini call: double check the key name in .env
      matches exactly GROQ_API_KEY or GEMINI_API_KEY, and that
      params.yaml -> llm.provider is set to the matching provider ("groq" or
      "gemini") -- these two must agree or it will error immediately.
    - If sentence-transformers fails to download the model: it needs internet
      access on first run to pull all-MiniLM-L6-v2 from Hugging Face (one-time,
      cached after that).
    - If it crashes partway through classification_baselines with a rate-limit
      error: Groq/Gemini free tiers have per-minute request limits. If you hit
      this, add a short time.sleep(0.5) inside the loop that calls
      classify_intent_llm in src/resolvai/components/classification_baselines.py,
      or reduce params.yaml -> classification.label_sample_size (e.g. to 300).

STEP 5 - Manually review the LLM-generated intent taxonomy
---------------------------------------------------------------
    Open config/intents.yaml after stage 3 runs. Read every intent name and
    definition. Fix anything that looks wrong, merge duplicates, rename badly
    named ones. Do NOT skip this -- it feeds everything downstream.
    If you change it, re-run from STEP 4 (stage 4 onward) so the classifier
    baselines reflect your corrected taxonomy.

STEP 6 - Generate and hand-label the golden set
-----------------------------------------------------
    python -m resolvai.pipeline.stage_06_golden_set_template

    This writes data/golden/golden_set_TEMPLATE.csv (150 rows, stratified by
    a rough intent guess + difficulty tag). Open this CSV yourself and fill in:
    - ground_truth_intent (correct the suggested_intent if it's wrong)
    - ground_truth_escalate (True/False)
    - escalation_reason (one short line)
    - good_reply_checklist (2-3 things a good reply must contain)

    Save the completed file as data/golden/golden_set.csv (exact filename,
    same folder). This is manual work only you can do -- there is no shortcut.

    Also write data/golden/SAMPLING_AND_LABELLING_METHODOLOGY.md: a few
    paragraphs on how you sampled (stratified by rough intent + difficulty),
    who labeled it (you), and known limitations (rough_intent came from a weak
    classifier so the suggestions could be wrong -- that's expected).

STEP 7 - Run the evaluation harness
----------------------------------------
    python -m resolvai.pipeline.stage_07_evaluate

    This computes intent accuracy/F1, escalation accuracy + false auto-handle
    rate, generates replies for every golden example and LLM-judges them, checks
    for golden/retrieval-set data leakage, and writes everything to
    data/golden/evaluation_results.json. It also writes data/golden/judge_scores.csv
    with the per-example judge outputs and generated replies -- this is your
    source material for the failure analysis section of the report.

    If data/golden/judge_calibration_scored.csv does not exist yet, this stage
    will skip the human/judge agreement calculation and print a warning telling
    you what to do next (see Step 8).

STEP 8 - Hand-score the judge calibration sample
------------------------------------------------------
    After Step 7, open data/golden/judge_calibration_TEMPLATE.csv (~35 rows).
    Score each one yourself on the same 4 axes (grounding, actionability, tone,
    safety, 1-5 scale) by adding columns human_grounding, human_actionability,
    human_tone, human_safety. You'll need the judge's own scores to compare
    against -- pull the matching rows from data/golden/judge_scores.csv (from
    Step 7) and add columns judge_grounding, judge_actionability, judge_tone,
    judge_safety to the same file.
    Save as data/golden/judge_calibration_scored.csv, then re-run Step 7 --
    it will now also print the kappa/agreement numbers.

STEP 9 - Run the smoke tests
----------------------------------
    pytest tests/ -v
    All should pass if Steps 1-4 completed. This is a sanity check, not a
    substitute for the manual verification above.

STEP 10 - Write the report and finish the decision log
-------------------------------------------------------------
    Now that data/golden/evaluation_results.json and judge_scores.csv have real
    numbers and real examples, fill in REPORT.md properly:
    - Problem framing: 1-2 paragraphs on what "good" means for this brand
    - Results vs. baselines: pull the table from
      data/processed/classifier_comparison.csv and evaluation_results.json
    - Failure analysis: sort judge_scores.csv by lowest scores per axis, pick
      5 real examples across intent errors / retrieval misses / generation
      errors, write a one-line hypothesis for each
    - Misleading number section: use the golden_retrieval_overlap_count value
      from evaluation_results.json, plus the other points already drafted in
      REPORT.md
    - Next steps with one more week

    Add 5-10 more entries to DECISION_LOG.md reflecting your actual choices
    (which brand and why, what threshold values you ended up with, any
    taxonomy corrections you made, etc.)
